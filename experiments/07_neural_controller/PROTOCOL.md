# PREREG_AXSUP_v1 — the unchanged layer on a trained neural controller (Residual PPO)


## Question
- Can the small, bounded layer improve an already trained neural controller without retraining it?
- Does the headroom account of Section 5.3 tell in advance whether it will?

## Controller
The public Residual PPO controller of alexchilton:
- Kaggle notebook "Yes, RL Can Run a Building: Residual PPO"; dataset smart-buildings-residual-rl; Apache-2.0.
- Weights skynet.pt, sha256 8b1b4d0a…, checkpoint fa2_all_from_s3_8m@7004160 (7.0M PPO steps). All 22 files match the dataset's MANIFEST.

The policy has two parts:
- **The rule:** the public zt rule of malyshevdanil (the same lineage as ZT Best), with CMA-tuned constants, a pre-start ramp and an off-hours rule.
- **The network:** a residual PPO network, with ONE shared network per entity type (zone, air handler, plant). It therefore runs on any building, and it may correct every command at every hour (controller "zt_off_all").

The author trained it on official training buildings 1, 2, 4, 5 and 7 in five climates. The blind set uses other buildings and 2022 weather, so it is out of sample for the network.

Safety and provenance:
- The weights are loaded with the safe loader (`torch.load(weights_only=True)`). Their pickle was inspected statically and imports only OrderedDict and torch tensor rebuild functions.
- The author's `load()` (`weights_only=False`) is never called.
- The source files were scanned before running and contain no file, network, process or code-execution calls.

## Runner and fidelity
`run_episode_k07_v9supe_ax.py` is generated by `axsup/make_runner_ax.py` from `run_episode_k07_v9supe_zt.py`, the runner of the ZT Best test:
- The supervisor code (learned optimal start and trim & respond) is byte-identical.
- Only the controller changes. The supervisor reads and writes the zt rule inside the controller (as on ZT Best), and trim & respond floors the FINAL static-pressure command, after the network's residual.

Fidelity (p275, development scenes 52010 phoenix_7 and 52103 fairbanks_3, 864 steps):
- **F2:** `k07sup@;ROS=0,TR=0` equals `k07@`, bitwise.
- **F3:** `k07sup@;ROS=1,TR=1` runs without illegal actions and is identical up to the supervisor's first action.

Nothing is launched unless both pass.

**Fidelity result** (`RESULT_AXSUP_FIDELITY.json`, laptop, 21:00): **ALL PASS.**
- **F2:** bitwise identical on both scenes.
- **F3:** the first difference falls at the supervisor's first action: phoenix_7 step 407 (a pressure override) and fairbanks_3 step 252 (a learned start).
- **Activity:** 149 override steps on phoenix_7; 3 learned starts on fairbanks_3, with τ moving 1.0 → 1.18 → 1.65 h.
- **Other:** 0 illegal actions; the controller takes about 9 ms per step; peak memory is 1.2–1.4 GB per run.

## Design: zero-shot, as the ZT Best maintenance test
- **Nothing is tuned:** neither the layer nor the controller. There is no development step.
- **Set:** the blind set K07-X3, 12 architectures (10 composite + 2 OOD) × 3 weather windows = 36 scenes, 8640 steps. The same scenes, kit, tracker overlay (KRE-v2) and stage runner as G30 / layer and ZT Best / layer.
- **Arms:** AX (`k07@`, the controller exactly) and AXS (`k07sup@;ROS=1,TR=1`), 72 runs.

## Analysis (p277, frozen with this file; the same rules as p252)
- **Loss and gain.** Loss = mean |reward| over 8640 steps. Gain = 100 (1 − Σ L_AXS / Σ L_AX), pooled over the 10 composite architectures, with a 95 % architecture-cluster bootstrap (3,000 replicates, seed 1).
- **Primary rule, "the layer helps the neural controller".** All three must hold:
  - the pooled gain is > 0;
  - most of the changed composite architectures are better;
  - no architecture is more than 1 % worse.
- **Also reported:**
  - OOD;
  - the weighted-component decomposition;
  - the supervisor's activity (learned starts, override share);
  - descriptive comparisons on the same scenes: AX against K07-G30 and ZT Best, and AXS − AX against the layer's gain on G30 and on ZT Best.

## Registered predictions of the headroom account (p278 = p258 with mode 'ax'; frozen with this file)
Definitions:
- s_e = the comfort share of AX's weighted loss (competition weights);
- g_e = 100 (1 − L_AXS / L_AX), over all 36 episodes.

Predictions:
- **P1.** Spearman ρ(g, s) > 0, with one-sided permutation p < 0.05.
- **P2.** The pooled gain of the third with the lowest s lies within [−0.5, +0.5] %.
- **P3.** If the mean s of AX is below K07-G30's 0.1329, the pooled gain is below 2.69 %; if above, it is above.
- **P4 (early indication).** The comfort share of AX's first week (days 1–7) ranks the gain over days 8–30 (Spearman ρ > 0).

Each prediction is reported as PASS or FAIL with its numbers.

## Specific risk, stated in advance
The network was trained with the rule's own start and its own pressure commands. The layer moves the start of the rule's PI hours and floors the pressure command. The network therefore meets states it never saw in training. A loss is a possible and reportable outcome, and a negative result goes into the paper as such.
